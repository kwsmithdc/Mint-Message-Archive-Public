# Android Installation

There are two supported ways to install the Android application.

## Option 1 — Build and install automatically with ADB

This is the easiest method for a Linux development computer that already has the Android SDK installed.

Connect the Android phone by USB, enable Developer options and USB debugging, and authorize the computer on the phone.

Then run:

```bash
curl -fsSL https://raw.githubusercontent.com/kwsmithdc/Mint-Message-Archive-Public/main/install-android.sh | bash
```

The installer:

1. Checks for ADB.
2. Checks for Java 17.
3. Checks for an Android SDK.
4. Clones or updates the public source tree.
5. Runs the Android unit tests.
6. Builds the debug APK.
7. Confirms exactly one authorized Android device is connected.
8. Installs the APK with `adb install -r`.

The script does not wipe the phone or remove unrelated applications.

### Android SDK prerequisites

If the installer reports that the Android SDK is missing, install Android Studio or the Android SDK command-line tools first.

The SDK must be available through either:

```text
ANDROID_HOME
```

or:

```text
ANDROID_SDK_ROOT
```

The Android project may also require the SDK platform/build tools selected by the Gradle build.

On Linux Mint, ADB and Java 17 can be installed with:

```bash
sudo apt update
sudo apt install adb openjdk-17-jdk
```

## Option 2 — Build manually

From a checkout of the repository:

```bash
cd android
./gradlew :app:testDebugUnitTest
./gradlew :app:assembleDebug
```

The APK is created at:

```text
android/app/build/outputs/apk/debug/app-debug.apk
```

Install it with:

```bash
adb install -r android/app/build/outputs/apk/debug/app-debug.apk
```

## Option 3 — Install an APK directly on the phone

A user can also copy the built APK to the Android phone and open it with a file manager.

Android may require permission to install applications from the application used to open the APK. Enable that permission only for the application you trust to perform the installation.

## First-time configuration

After installation:

1. Open **Mint Message Archive**.
2. Configure the Linux archive server URL.
3. Enter the authentication token generated by the Linux installer.
4. Save the server configuration.
5. Run **Scan Messages**.
6. Run **Backup Now**.
7. Confirm that the backup succeeds.
8. Open the Linux archive web interface and verify that the messages and attachments are present.

The server URL should point to the Linux computer's **local-network address**, for example:

```text
http://192.168.x.x:8765/
```

Do not use a public Internet address. The application intentionally rejects public server destinations.

## USB debugging

ADB installation requires USB debugging.

On the phone:

1. Open **Settings → About phone**.
2. Tap **Build number** repeatedly until Developer options are enabled.
3. Open **Developer options**.
4. Enable **USB debugging**.
5. Connect the phone by USB.
6. Approve the computer's RSA authorization prompt.

Verify the connection with:

```bash
adb devices
```

The device should appear with status:

```text
device
```

Do not proceed if the status is `unauthorized`.

## Multiple phones

The project supports multiple Android phones.

When installing the application on additional phones:

- install the same application;
- configure each phone with the same Linux archive server;
- give each phone a distinct device alias if desired;
- keep each phone's Android identity intact.

The Linux server keeps each device's archive independently.

## Privacy and network behavior

The Android application does not send archive data to a cloud service.

Archive uploads are intentionally restricted to local/private network destinations. The Linux server separately validates the connecting client's address.

The Android application requests access to message and media data only because those permissions are required to create the archive.
